# 旧版改造任务清单（权威）

本文件记录用户明确提出的要求，按此执行；不要在会话里遗漏或改口。

## 前提

- 基于旧版 `v0.1.26` 的实现向上改；保留旧版原有产品层（UI、助手工具、任务托盘、提示词与技能、关系网、伏笔、能力体系等）。
- 只替换存储层：去掉 SQLite，改为文件存储（已基本完成：`file-store.js` + `storage/*`）。
- 不保留旧数据迁移，不写导入器。

## UI 要求

1. **删除旧版大纲/正文的多形态视图**
   - 旧版大纲与章节页有“卡片 / 表格 / 图谱”等切换，用户判定为坏点子（无用、增加复杂度）。
   - 改为单一视图，不再提供多形态切换。

2. **文件树式导航**
   - 用常驻文件树（项目 / 卷 / 章 → 章卡 / 正文 / 摘要）取代“步骤页 + 页内切换”。
   - 切换文档只换右侧内容，不丢当前焦点，不需要来回长大纲/正文页。

3. **右侧栏对照信息**
   - 看正文时，右侧栏显示本章章卡细节（目标、场景、人物、伏笔、字数进度、上一章交接），不跳转。
   - 看章卡时，右侧栏显示正文是否存在、净字数、最近修订、连续性摘要。
   - 右侧栏可折叠、窄屏收起。

4. **资料库（新版功能，移植到旧版）**
   - 原作 / 我的前作 / 研究资料 / 灵感四类。
   - 类型要能编辑（现在只能筛选，看不出作用）；类型要有语义，影响 AI 引用方式。

## 助手与流程要求

5. **不开写作台、纯对话自动完成写作**
   - 在 DSH 普通对话里即可初始化项目、生成提案、写盘，不依赖打开写作台 UI。
   - 需要验证旧版 `novel_*` 工具在当前 DSH 宿主可注册、可工作。

6. **11 种任务模型粒度保留**
   - 构思、设定与人物、章纲、正文草稿、正文修订、质检修复、风格审稿、章节摘要、连续性检查等按任务配模型与思考档（旧版已有，保持）。

## 质量要求

7. 稳定（回归测试全绿）、易用、美观，效果要好。
8. 无用代码在依赖清理后删除（当前 `db.js` / `store.js` / `migrate.js` 仍被旧测试夹具依赖，先改夹具再删）。
