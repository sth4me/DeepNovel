# 自定义

## 文风

- 内置模板作为起点。
- 文风契约所有字段可改：视角、时态、单章字数、句长、段落长度、对话占比、比喻密度、叙述声音、用词偏好、意象、感官侧重、对白写法、节奏、三档规则（必须贯彻 / 绝对禁止 / 按场景调节）、禁用词、禁用句式、适用题材、章节标题风格、额外要求。
- **示例段落**：文风页可粘贴 2–3 段语感示例（空行分隔），每段建议 80–150 字，覆盖不同场景（日常 / 冲突 / 情绪）；保存到契约后作为「文风示例」段进入提示词，比字段描述更能锚定语感。
- 「保存为模板」写入 `style_templates` 表（含示例段落）；下次可在模板列表套用。
- 模板可**导出**为 JSON（复制剪贴板）或**导入** JSON 为新的自定义模板。
- 自定义模板可删除；内置模板不可删除。

## 自动化

项目 → 自动化与目标：

- 生成后自动跑 AI 风格检测
- 生成后自动修复（含检测）
- 多轮修复轮数（1–3）
- AI 风格通过线（0–100）
- 连续写章默认数量
- 全书目标字数

## 上下文预算

项目 → 上下文预算：

- 最近状态章数、上一章结尾字符数
- 角色/规则/未回收伏笔/时间线上限
- 是否带伏笔

## 模型

项目 → 模型分配：

- 每个任务可选 provider/model 与思考等级，或继承 DSH 当前默认。
- 正文类默认关闭/低思考；审稿默认低思考。

## System 模板

项目 → System 模板（高级）：

- 按任务覆盖**基础 system prompt**：构思 / 设定 / 大纲 / 正文 / 修订 / 修复。
- 留空 = 使用内置默认；覆盖只替换基础 system，任务附加规则（如“这是修复任务，不改情节”）仍由插件拼接。
- 存储于 `story/project.db` 的 `prompt_overrides` 表（v2 结构 `{ version: 2, overrides: { [key]: { text, baseHash, baseRevision } } }`；旧版纯字符串格式仍可读）。
- 覆盖会记录「基于哪个内置版本」：插件升级内置默认后，提示词页显示「默认已更新」徽标；**未真正改过**的覆盖自动跟进新版默认，改过的保留你的版本，并提供「改用新版默认」一键恢复。
- 与「提示词注入」互补：注入只追加，System 模板替换基础段。

## 提示词注入

项目 → 提示词注入：

把一段自己写的文本追加到系统提示词，用来补充写作口径、内容边界或输出要求。注入只做追加，不覆盖插件内置提示词；清空并禁用后恢复原状。

| 作用域 | 存储位置 | 生效范围 |
|---|---|---|
| 项目级 | `story/prompt.json` | 仅本项目的模型调用（草稿、修订、修复、构思、设定、大纲、审稿） |
| 全局级 | `~/.dsh/novel-writer/prompt-injection.json` | 所有项目的模型调用，并追加到 DeepNovel 预设（`novel-writer`）会话的系统提示词 |

- **注入位置**：追加到系统提示词末尾（默认，模型对靠后指令更敏感）或放在开头。
- **应用任务**：默认只作用于正文 / 修订 / 修复；切到「全部任务」后构思、设定、大纲等 JSON 任务也会注入，注入文本要避免与 JSON 输出要求冲突。
- **叠加顺序**：全局级在前、项目级在后；同级多条按 prefix / suffix 分别拼接。
- **JSON 修复请求不注入**：模型输出无法解析时的修复调用始终使用原始修复提示词，避免注入内容干扰格式修复。
- **立即生效**：全局级通过预设作用域的函数式提示词段注册，每次系统提示词组装时重新读取文件，保存后无需重装插件或重建会话；项目级在每次模型调用时读取 `story/prompt.json`。
- **可审计**：`story/project.db` 的 `runs` 表记录的是实际注入后的 system，便于排查注入是否生效。

手动改文件也可以：两个 JSON 都是 `{ enabled, position, tasks, text }`，`tasks` 为空数组表示全部任务。全局级文件不存在时视为未启用。

## 手动改数据

正文是 `story/chapters/NNN/*.md`，可直接编辑，插件读取以文件为准；修改已确认内容后，下游可能标记 stale，需要重新生成或确认。结构化数据在 `story/project.db`，不建议直接改库文件，诊断时用只读的 `novel_query` 工具查看。

## 解除初始化

项目页提供“危险操作：解除初始化”。

- **自动解除**：两次确认后，把 `story/` 与 `.dsh-writing/` 移动到项目内的 `.deepnovel-backup/<时间>/`，写作台回到未初始化；不会直接删除，备份可手动恢复或删除。
- **手动解除**：
  1. 先把整个项目（至少 `story/` 与 `.dsh-writing/`）备份到项目目录之外；
  2. 关闭正在运行的任务；
  3. 删除 `story/` 与 `.dsh-writing/`，只删这两个；
  4. 重新进入写作台，会显示未初始化。
- `exports/` 不会被自动移走，需要时自行处理。

## 技能库

内置 9 张通用技法卡片以 `craft-*` 作为内置技能（随插件提供、不可删除、可按项目开关），与项目导入、全局导入技能平级出现在技能目录；不加载 DSH 公共 / 用户级技能。

- 内置开关：项目页「技能库」逐条启用/停用（写 `story/project.db` 的 `project` 表中的 `craftDisabled`）。
- 导入技能：把 `SKILL.md`（目录包或单个 `.md`，YAML frontmatter 含 name/description）通过项目页「导入技能」导入；可选择作用域——项目写入 `<projectRoot>/.dsh/skills`（仅当前项目），全局写入 `DSH_HOME/novel-writer/library/skills/`（所有写作项目可用）。同名覆盖前会备份（项目 → `.dsh-writing/backups/skills-<时间>/`，全局 → `DSH_HOME/novel-writer/library/backups/skills-<时间>/`）。也可手动放到项目的 `.dsh/skills`、`.agents/skills` 或全局库。
- 优先级：同名冲突时 项目 > 全局 > 内置。
- 路由：AI 用 skill 工具按需读取全文并自行判断是否适合本章；不再由程序按任务打分注入。
- 旧兼容：`$DSH_HOME/novel-writer/library/craft/<id>.json` 自定义卡片与 `novel_craft` 工具（list / read / recommend）仍可用。

## 拆书

- 三阶段流水线：结构编年（分段单元 + 剧情功能）、人物与设定（角色/地点/规则/势力/物品/关系）、技法与钩子（可复用桥段、写法、节奏观察）。
- 单阶段失败不影响其它阶段，结果里会标出失败阶段；历史保留最近 10 条。
- 只依据粘贴文本提炼，不编造未出现的内容，也不评价文笔。

## 暂未支持

- 构思/大纲模板
- 从样文自动提取文风模板（「拆书」可提炼梗概与桥段，但不直接生成文风模板）
- PDF 直接导出（HTML 可打印 PDF）
