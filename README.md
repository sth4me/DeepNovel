# DeepNovel

DeepNovel 是一个面向长篇小说创作的 DSH 插件：把写作台做成独立的主面板，在固定流程里完成构思、设定、大纲、章节、质检与导出。

仓库只包含插件本身和项目文档。实际小说数据不属于本仓库，默认由插件写到用户选择的项目目录，`story/`、`exports/` 已被忽略。

## 功能

- **主面板写作台**：不依赖会话即可开始；侧栏「写作台」入口，项目目录独立。
- **固定流程**：项目 → 构思 → 文风 → 设定 → 大纲 → 章节。
- **构思**：生成候选、比较、确认、编辑；**灵感模式**（生成桥段点子，可一键用作方向，历史落盘）；**拆书**（粘贴已有文本，三阶段流水线拆出结构编年、人物与设定、人物关系、技法与可复用钩子；单阶段失败不影响其余结果）。
- **文风**：9 个内置文风模板（快节奏网文 / 文学向 / 悬疑冷硬 / 轻松日常 / 古风仙侠 / 古风言情 / 冷硬江湖 / 科幻硬核 / 都市现实），每个模板带结构化字段（视角、句长、对白、叙述声音、用词、意象、感官侧重、节奏）+ 三档可执行规则（必须贯彻 / 绝对禁止 / 按场景调节）+ 2–3 段示例段落；字段可微调，模板可保存/删除/套用/导入/导出。
- **设定**：角色、地点、规则、势力、物品；生成、编辑、确认；角色卡带性格标签与目标，可导入/导出；**跨项目角色库**（角色卡存入库，其他项目一键导入/合并，库在 `DSH_HOME/novel-writer/library/`）。
- **人物关系**：独立的关系表（`story/project.db` 的 `relations`）；SVG 关系网、节点拖拽与布局保存、导出 SVG/PNG；章节生成按出场人物注入关系。
- **伏笔看板**：埋设/回收时间线、未回收高亮、点章号跳大纲；章节页另有本章伏笔提醒。
- **能力体系**：境界层级、角色当前战力、按章能力变化；写正文与审校都会读取，防止无铺垫跨级。
- **大纲**：生成、重生成、卡片/表格/**图谱**/编辑视图、逐章/全部/本卷确认；多卷创建、按卷生成、章节移动；图谱可导出 SVG/PNG。
- **章节**：草稿、规则质检、AI 风格审稿、多轮修复、单轮修复、局部重写逐块预览/应用/撤销、**润色/扩写/缩写**、整章手动编辑、修订历史 diff/恢复、定稿、连续写章、按卷「写本卷剩余 / 定稿本卷草稿」；阅读时顶部操作条固定，选段可开关，质检问题可定位段落。
- **长篇记忆**：定稿自动生成章节摘要，最近摘要 + 按章纲关键词检索的相关摘要进入写作上下文；角色索引；确定性连续性检查 + AI 连续性检查。
- **数据健康**：项目页汇总章纲未确认/缺字段、草稿未定稿、坏关系、超字数、摘要缺失、伏笔停滞，并支持一键补摘要/确认章纲/批量定稿/清理坏关系/刷新过期定稿。
- **项目安全**：项目快照创建/恢复（含数据库与正文，复制前先 checkpoint WAL）；解除初始化前自动备份。
- **数据层**：结构化数据存 SQLite（`story/project.db`，WAL），正文保持 Markdown；旧项目首次打开自动迁移并保留旧 JSON 只读存档；支持导出 / 导入纯文件项目（互逆，导入前自动备份）、重建检索索引与数据状态；多窗口并发安全（WAL + 重试），可同时写不同章节。
- **并行任务**：按章/按阶段锁；同资源动作自动排队；任务托盘显示动作、真实阶段与耗时，支持单项重试/取消、连续写章当前章后暂停；写作助手与界面共用同一套资源锁，助手占用会显示在托盘，冲突操作自动禁用。
- **上下文管理**：故事背景、文风（含示例）、相关设定、人物关系、最近状态、上一章结尾、未回收伏笔、时间线、作者备注；可按项目预算裁剪并预览实际 token。
- **技能库**：内置技能共 14 个——9 张技法卡片（`craft-*`）与 5 个参考库（`ref-hooks` 钩子库、`ref-openings` 开篇库、`ref-reversals` 反转工具箱、`ref-emotional-arc` 情绪弧线、`ref-quality` 质检清单），随插件提供、只能按项目开关、不可删除；另支持项目导入（`<projectRoot>/.dsh/skills`、`.agents/skills`）与全局导入（`DSH_HOME/novel-writer/library/skills/`，所有写作项目可用），项目优先于全局、全局优先于内置；不加载 DSH 公共 / 用户级技能；AI 用 skill 工具按需读取全文，自行判断是否适合本章（题材 / 文风契约 / 节奏 / 指令），不适合不套用；技法不是本书设定、不是硬性规则；项目页可开关 / 导入 / 删除 / 预览。
- **素材库**：片段 / 资料 / 桥段 / 引用等参考素材，项目页可新增、编辑、删除，按类型与标签管理；素材不会自动注入提示词，由助手按需查询。
- **项目写作要求**：项目级共享要求，自动注入设定/大纲/草稿/修订；可按阶段开关，支持预设（全部 / 仅正文 / 大纲+正文）。
- **按任务模型**：从 DSH 模型目录为不同任务选择模型与思考等级；正文类任务默认关闭/低思考。
- **System 模板**：按任务（构思/设定/大纲/正文/修订/修复）覆盖基础 system，留空用默认；覆盖记录所基于的内置版本，插件升级默认后提示「默认已更新」，未真正改过的自动跟进新版。模板按分类（构思/设定/大纲/正文/审校/技法/数据/其他）筛选，可预览默认与当前生效文本、覆盖状态、版本与 `{{name}}` / `${name}` 占位符；预览只读。
- **提示词注入**：项目级 / 全局级追加自定义提示词到系统提示词；全局级同时作用于 DeepNovel 预设会话，保存即生效。
- **写作台对话**：AI 页内嵌 DSH 官方对话界面；每个项目一个隐藏会话（DSH 子代理，不出现在侧栏），复用 DSH 的模型、工具与上下文压缩；支持新对话与摘要接力、一键压缩对话上下文，重启后自动恢复父会话并继续原对话。助手通过 `novel_*` 工具读写项目，支持碎片化改正文（`novel_chapter action=patch`，只替换片段、不调用模型）、工具报错可恢复、感知数据层规则；查询面覆盖大纲/设定/关系/能力/灵感/素材/拆书/提示词覆盖/构思对话；详见 [写作助手](docs/AI-ASSISTANT.md)。
- **外部能力**：预设已挂载 skill 与 MCP 客户端；技能目录含内置技法技能（`craft-*`）与导入技能，项目页可开关 / 导入 / 删除；MCP 服务器按条目配置（工具名 `mcp__<serverName>__<tool>`）。
- **去 AI 味**：风格审稿与统一审校输出 `aiFlavor` 等级与命中标记（35 个一级禁用词 / AI 句式 / 结构指纹 / 真人基准）；章节页「去 AI 味」一键改写（先预览、只改表达、带修订备份、字数护栏）。
- **运行详情**：最近运行可按类型筛选，查看每次调用的 system、输入与输出，支持复制输出。
- **状态与导出**：故事时间线、伏笔列表、写作统计、结构统计（伏笔回收率/卷字数/出场 Top）；Markdown / HTML / EPUB / DOCX（含标题与目录域）导出。
- **响应式与专注模式**：三栏工作台、可收起检查器、窄屏步骤选择、专注模式。

## 安装

前提：本机已运行支持插件系统的 DSH，并已在 DSH 中配置好可用模型。

1. 在 DSH 的插件管理里安装本仓库根目录（bundle）。GitHub 地址安装时，包根就是仓库根。
2. 启用后打开写作台入口。
3. 首次进入选择一个**空目录**或已有 DeepNovel 项目目录；不要在插件仓库目录里初始化小说数据。

开发时也可以把仓库根目录以本地 link 方式装入 profile。修改 `client.js` 后客户端 HMR 会热替换；Host 代码变更通常需要重新安装/重载插件。

## 快速开始

1. 打开「写作台」。
2. 选择一个项目目录（例如 `~/Novels/my-book`）。
3. 初始化项目。
4. 按流程完成构思 → 文风 → 设定 → 大纲。
5. 在章节页生成草稿、质检、修复、手动改，最后定稿。
6. 在项目页导出 Markdown 或 HTML。

项目数据由插件管理。结构化数据存 `story/project.db`（SQLite，WAL），正文是 Markdown 文件：

```text
story/                 # 小说数据（不属于本仓库）
  project.db           # 结构化数据：项目/构思/文风/设定/关系/能力/章纲/状态/摘要/统计/运行记录
  prompt.json          # 项目级提示词注入
  chapters/NNN/        # 正文：draft.md、final.md、revisions/
exports/               # 导出文件（不属于本仓库）
.dsh-writing/          # 动作日志、灵感/拆书历史（不属于本仓库）
```

旧项目（只有旧版 JSON、没有 `project.db`）首次打开会自动迁移；原 JSON 保留为只读存档。

## 写作助手扩展（skill / MCP）

写作助手（`novel-writer` 预设）支持 DSH 的项目级 skill：在项目根目录建 `.dsh/skills/<name>/SKILL.md`（或扁平 `<name>.md`），文件头写 YAML frontmatter，`name` 与 `description` 必填：

```markdown
---
name: my-skill
description: 一句话说明这个 skill 什么时候用
---

这里写具体指令。
```

助手会话只会发现**项目内**的 `.dsh/skills` 与 `.agents/skills`（以及插件内置的 `craft-*` 技法），不会加载 DSH 的公共 / 系统 / 用户级技能；新增/改名/删除无需重启。

MCP 服务器默认不启用（避免启动时连接失败拖慢）。`cordis.patch.yml` 里有一个 `mcp-example` 条目（`disabled: true`）：把 `disabled` 改成 `false`，按需填写配置即可，每个服务器一个条目：

```yaml
- id: mcp-my-server
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: my-server          # 工具名命名空间：mcp__<serverName>__<tool>
    transport: streamable-http     # 或 stdio
    url: http://127.0.0.1:3000/mcp
    # stdio 时改用 command/args/env/cwd
```

启用后该服务器的工具会以 `mcp__<serverName>__<tool>` 的名字出现在助手工具列表里。

## 开发

```powershell
node --check service.js
node --check index.js
node --check client.js
node --check agent.js
node --check templates.js
```

改动后的固定更新流程见 [发布与更新流程](docs/RELEASE.md)：本地验证 → 提交推送 → 在 profile 重新安装 → 重启/刷新。不要手工拷贝文件到 profile，插件管理器更新会把它覆盖回旧版本。

运行记录写入 `story/project.db` 的 `runs` 表，动作日志写入 `.dsh-writing/actions.log`，都不会进入仓库。

非破坏性接口检查：

```powershell
node scripts/test-api.mjs D:\path\to\your\novel
```

读取项目状态、模型目录与第 1 章上下文预览，不生成、不写文件。

## 说明

- 仓库不包含任何小说正文、设定或导出文件。
- 插件通过 DSH 的模型/文件/Web 服务工作，不额外引入模型 SDK。
- 导出支持 Markdown / HTML / EPUB / DOCX；PDF 用浏览器打印生成。
